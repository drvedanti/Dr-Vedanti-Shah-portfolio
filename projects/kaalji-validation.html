India 2050 · KAALJI · Validation Plan

How would I know if KAALJI is actually worth building?

A prototype can be persuasive and still be wrong. Before expanding KAALJI, I would test whether its evidence checks and explanations actually help people reason more accurately about a care-system problem — and whether that changes what they do next.

The product should be allowed to fail. If the evidence is too weak, the workflow sends people in the wrong direction, or users make the same decisions without KAALJI, I would reshape or stop the concept.
1

Can the evidence support the question?

Before testing the interface, I would first check whether the important care questions can actually be answered — or honestly bounded — with available evidence.

How I would test it

Take a set of real care-capacity questions and run the sources through KAALJI's comparison checks: same population? same time period? same definition? same stage of the system?

A good result looks like

KAALJI can either support a comparison with traceable evidence or clearly explain why the evidence is not strong enough.

Warning sign: Most useful questions remain unanswerable and KAALJI adds little beyond a list of links and reports.
2

Does it point us toward the right next question?

KAALJI should not pretend to know the answer. Its value is helping someone investigate the most useful next piece of evidence.

How I would test it

Use care-system cases where additional information can later be obtained. Compare KAALJI's suggested next investigation with what the new evidence eventually reveals.

A good result looks like

The suggested evidence helps rule out weak explanations and focus attention on the explanations that still make sense.

Warning sign: The product repeatedly recommends irrelevant information or makes a weak explanation look more convincing than it is.
3

Do people understand the evidence better?

This is the clearest early user test: does context help someone avoid jumping to an unsupported conclusion?

How I would test it

Give two groups the same care-capacity problem. One sees only the numbers. The other sees KAALJI's source context, comparison warning, known/unknown view and next question.

A good result looks like

People using KAALJI are better at separating facts from assumptions and can explain what the numbers do — and do not — prove.

Warning sign: The extra context makes the task more complicated without improving the quality of interpretation.
4

Does it change what someone does next?

A product can be interesting and still have no decision value. The strongest test is whether KAALJI changes the next action in a sensible way.

How I would test it

Observe a realistic planning task with and without KAALJI. What data does the person request? Which assumption do they investigate? Do they reject a misleading comparison?

A good result looks like

The next action becomes more evidence-based — for example, asking for employment data before deciding to fund more training.

Warning sign: Users like the interface, but still make the same unsupported decision they would have made without it.

The first experiment I would run

Question: Does showing evidence context reduce unsupported conclusions compared with showing numbers alone?

Version A — Numbers only “36,785 caregivers trained.”

Ask the user: What does this tell you about caregiver availability?
VS
Version B — KAALJI view Training figure + what it measures + what it cannot prove + missing employment/availability evidence + next question.

What I would watch: How often people make an unsupported shortage/supply claim, whether they identify the missing evidence, and the quality of the next question they ask.

One extra check for AI

If AI is used to help find or explain evidence, I would separately test whether it keeps the correct source, preserves labels such as fact vs hypothesis, and handles conflicting evidence without inventing an answer. Speed is useful only if evidence discipline is not lost.

When I would stop or reshape KAALJI

I would not keep building simply because I had already invested time in the idea. I would reconsider it if:

  • the evidence base is too weak for the questions users actually care about;
  • users do not need help interpreting the evidence;
  • the workflow does not improve the next investigation or decision;
  • existing tools already solve the job well enough.
